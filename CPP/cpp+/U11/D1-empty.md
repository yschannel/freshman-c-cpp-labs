| 数据需求场景                               | 推荐使用的 STL 容器 | 选择依据                         | 暂不推荐的容器及理由                                                 |
| ------------------------------------------ | ------------------- | -------------------------------- | -------------------------------------------------------------------- |
| 保存一组成绩，并按输入顺序依次输出         |                     |                                  | `set` 不适合，因为                                                   |
| 已知第几个元素，需要快速访问该位置的数据   |                     |                                  | `list` 不适合，因为                                                  |
| 需要在队首和队尾都能较快插入、删除数据     |                     |                                  | `vector` 不适合，因为                                                |
| 保存一组不允许重复的编号，并能自动保持有序 |                     |                                  | `vector` 不合适，因为                                                |
| 根据学生姓名快速查询跑步距离               | map                 | 键值对快速匹配                   | `vector` 不合适，因为                                                |
| 模拟“最后放入的任务最先处理”               | stack               | 先进后出，后进先出               | `queue` 不适合，因为原则先进先出                                     |
| 模拟排队办理业务，先到先处理               | queue               | queue先进先出，后进后出          | `stack` 不适合，因为其原则是先进后出，后进先出                       |
| 每次都需要取出优先级最高的任务             | priority_queue      | 满足优先级高的元素先出队列的需求 | `queue` 不适合，因为规则是先进先出，不满足优先级别高的元素先出的原则 |
